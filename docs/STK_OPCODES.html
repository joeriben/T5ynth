The 27 STK opcodes

Perry Cook and Gary Scavone's Synthesis ToolKit, reachable from an LRO body since the rawwaves ship inside the app. What each one is, what it does untouched, and every control it has.

How you call one. Frequency and amplitude, then any number of (control, value) pairs:

asig STKModalBar 220, 0.3, 16, 1, 2, 64, 4, 20
                 ─┬─  ─┬─  ─┬──  ─┬──  ─┬──
                  Hz  amp   │     │     └ strike position 20
                            │     └ stick hardness 64
                            └ preset 1 = Vibraphone

Values run 0–128 whatever the control means; STK divides by 128 internally. The pairs are optional, order does not matter, and a control the instrument does not know is ignored — which is why a wrong number fails silently instead of erroring.

The one thing that decides whether any of this is usable. Frequency is an i-rate argument — STKBowed kfreq, … does not even compile — and the LRO host starts each voice once, for 100 hours, and never restarts it. So a plainly written STK body takes its pitch at engine build and then, under a played note, is silent. The lever is reinit, which re-runs a marked block's i-time code on the note edge:

ktr changed2 ktrig          ; ktrig flips at note-on
if ktr == 1 then
  reinit strike             ; ← re-run everything from the label
endif
strike:
asig STKModalBar i(kfreq), 0.3, 16, 1, 2, 64
rireturn

Measured at 220 Hz: without it, silence. With it, a struck bar at −5 cents, decaying 0.056 → 0.0004 → 0. Still unmeasured, and gating any entry that ships on one of these: reinit re-runs STK's constructor, which is where it opens its data file, and inside the plugin Csound runs on the audio thread.

Read the numbers here, not the Csound manual. The bundled module was built against an older STK than the 5.0.1 source these tables come from, and the two disagree in one measured place: on STKShakers, decay sits on control 4 and object count on 11 — the reverse of what 5.0.1's symbols say, and matching the stale inline comments that Csound's manual copied. Everywhere else source and render agree. A ● marks a control that demonstrably changed the sound in a sweep of the shipped module; ○ means it did not move that render, which is not a disproof — several are inaudible until something else is set.

Stochastic particles, and samples

STKShakers is PhISEM, Cook's stochastic event model — the same physics as Csound's own shaker/guiro/cabasa, but with the object count and decay on knobs. STKDrummer plays STK's rawwave drum samples.
