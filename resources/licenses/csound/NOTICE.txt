Csound and its audio-file libraries, as bundled with akróasys
=============================================================

akróasys plays its language-resonant oscillator (LRO) through Csound: the
orchestra code that an LRO sound consists of is compiled and run by the Csound
library at runtime. That library, and the audio-file libraries it needs, are
bundled inside this application:

    Contents/libs/CsoundLib64            the Csound library itself
    Contents/libs/Opcodes64/*.dylib      Csound's plugin opcodes
    Contents/libs/lib*.dylib             the audio-file libraries Csound needs

Nothing here is linked statically, and nothing here is modified: each file is a
copy of the shared library as built by its own project, with only its recorded
load paths rewritten so that it is found inside this bundle instead of in a
system-wide location.

Replacing the Csound library with your own build
------------------------------------------------

The LGPL asks that you be able to run this application against your own version
of the library. You can:

  1. Build or obtain your own CsoundLib64 for this architecture (Csound 6.18.x;
     akróasys uses the Csound 6 C API: csoundCreate, csoundCompileCsdText,
     csoundPerformKsmps, and the named-channel calls).

  2. Record the load path this bundle expects:

         install_name_tool -id @loader_path/../libs/CsoundLib64 CsoundLib64

  3. Put it in place of Contents/libs/CsoundLib64. If your build needs plugin
     opcodes of its own, replace Contents/libs/Opcodes64/ with yours as well —
     akróasys points Csound at whatever that directory contains.

  4. Re-sign the application, because macOS refuses to load a library that the
     application's signature does not cover:

         codesign --force --deep --sign - akroasys.app
